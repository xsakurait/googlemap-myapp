## 2. モジュール詳細

### 2.1 src/lib/types.ts（型定義）

アプリ全体の型の正。SearchParams、OriginInput、NormalizedRoute、RouteSegment、ApiError（コードと HTTP ステータスを持つ例外クラス）、RoutesApiResponseBody を定義する。型の詳細は docs/08_クラス図.md を参照。

### 2.2 src/lib/time.ts（時刻ユーティリティ）

| 関数 | 役割 |
|---|---|
| computeDepartureIso(now, offsetMinutes) | 現在時刻＋オフセット分を ISO 8601 で返す |
| parseDurationSeconds(value) | "123s" 形式や数値を秒へ変換する |
| formatHm(iso) | ISO 8601 を HH:mm 表示へ整形する |
| formatDurationJa(minutes) | 分を「1時間5分」形式へ整形する |
| formatDurationSecondsJa(seconds) | 秒を日本語の所要時間表示へ整形する |

### 2.3 src/lib/google-client.ts（Routes API クライアント）

| 関数 | 役割 |
|---|---|
| parseSearchParams(body) | リクエスト JSON を検証し SearchParams を返す。不正時は ApiError（INVALID_PARAMS／400） |
| buildRequestBody(params, now) | Compute Routes のリクエストボディを構築する（FieldMask は FIELD_MASK 定数が正） |
| fetchRoutes(params, { apiKey }) | POST directions/v2:computeRoutes を呼び、応答を normalizeRoutes で正規化して返す。上流エラーは UPSTREAM_ERROR／502、0件は NOT_FOUND／404 |

出発地は座標（latLng）を Waypoint に直接渡し、住所文字列は address として渡す。Geocoding API は使わない。

### 2.4 src/lib/routes-normalize.ts（正規化）

| 関数 | 役割 |
|---|---|
| normalizeRoutes(json) | Google の routes 配列を NormalizedRoute 配列へ変換する |
| fareToYen(route) | localizedValues の運賃テキストから円を抽出する。取れなければ null |
| segmentFromStep(step) | steps を RouteSegment（transit／walk）へ変換する |

乗り換え回数は TRANSIT ステップ数 − 1（下限 0）。legs が無いルートは除外する。

### 2.5 src/lib/ranking.ts（並び替え）

| 関数 | 役割 |
|---|---|
| scoreRoutes(routes) | 総合スコアを付与する。重みは運賃 0.4／所要時間 0.3／乗り換え 0.3（WEIGHTS 定数）、min-max 正規化、運賃 null は候補内の最大運賃として扱う |
| sortRoutes(routes, mode) | recommend／fare／transfers／duration で並び替える。fare は運賃が確定した候補内での最安順 |
| computeBadges(routes) | 最安・最速・乗換最少のバッジ判定を返す |

### 2.6 src/lib/cache.ts（キャッシュ）

createCache（TTL 既定 60 秒）で Map ベースのメモリキャッシュを提供する。キーは cacheKeyFor（stableStringify によるキー順非依存の文字列化）で生成する。インデックス定義としての位置づけは docs/11_共通項目定義.md を参照。

### 2.7 src/lib/usage.ts（使用量カウンター）

純関数群（永続化は呼び出し側の localStorage）。

| 関数 | 役割 |
|---|---|
| monthKey(date) | Asia/Tokyo 基準の YYYY-MM を返す |
| loadUsage(raw, now) | 保存値を読み、月が違えば 0 にリセットした状態を返す（遅延評価） |
| serializeUsage(state) | JSON 文字列化する |
| checkLimit(state, warnAt, stopAt) | ok／warn／stop を判定する |
| increment(state, now) | 1 件加算した新状態を返す。月が変わっていれば新月の 1 件目にする |

### 2.8 src/app/api/routes/route.ts（API ルート）

POST /api/routes の処理順序は次のとおり（詳細は docs/09_シーケンス図.md）。

1. リクエスト JSON のパース（失敗時は INVALID_PARAMS／400）
2. parseSearchParams で検証
3. computeDepartureIso で出発時刻を算出
4. mock=true ならモック応答を返す（API キー不要・カウンター対象外）
5. API キー未設定なら API_KEY_NOT_SET／503
6. キャッシュヒット時は cached=true で即時応答
7. fetchRoutes で取得し、キャッシュへ登録して応答

### 2.9 src/app/page.tsx（画面 SCR-001）

単一画面。状態は出発地（GPS／手入力）、目的地、出発オフセット、並び替えモード、検索結果、使用量、設定、履歴を持つ。検索前に checkLimit でガードし、stop のときは API を呼ばず LIMIT_REACHED を表示する。成功時はカウンター加算と履歴追加（最大 10 件）を行い localStorage へ保存する。条件変更 UI（プルダウン）の仕様は docs/00 §5.1 に従う。
