# 要件定義書：電車ルート検索アプリ（Next.js）

作成日：2026-11-17
ステータス：作れる（条件付き。下記「成立条件」と「最安値の定義」を参照）

## 1. 目的

目的地を入力すると、デフォルトでは現在時刻を基準に「次の便」から検索し、
最安・最短・乗り換え最少を総合したおすすめルートを先頭に表示する個人用Webアプリ。
「今から○分後」への変更や、安さ／早さ／乗り換え少なさへの寄せ方は任意で選べる。
利用は無料枠の範囲内に収めることを最優先の制約とする。

## 2. 実行分担

| 担当 | 内容 |
|---|---|
| Muse（クラウド） | Next.jsアプリのコード作成、テスト、ビルド確認、ZIPでの交付 |
| ユーザーのPC | アプリの配置と起動（localhost）。Google Cloudプロジェクト作成、課金アカウント紐付け、APIキー発行、`.env.local` へのキー入力 |
| Google Routes API | 実際の電車ルート・時刻・運賃データの提供 |

APIキーはユーザーのGoogleアカウントに紐付くため、発行と課金設定はユーザー本人しかできない。
キーはチャットに貼らず、PC上の `.env.local` にのみ保存する。

## 3. 使用APIと無料枠（2026-11-17にGoogle公式ページで確認）

- 使用API：Google Routes API（Compute Routes）、`travelMode: "TRANSIT"`
- SKU：Routes: Compute Routes Essentials
  - 無料枠：月10,000リクエスト（公式料金表で確認）
  - 超過時：$5.00 / 1,000リクエスト（〜100,000件の帯）
- 無料枠内に収める設計上の工夫：
  - 駅名・住所の入力は文字列のままRoutes APIの `address` に渡し、Geocoding／Places APIは使わない（別SKUを消費しない）
  - 現在地GPSの座標も、逆ジオコーディングせずRoutes APIの出発地に緯度経度（latLng）のまま渡す（公式仕様で混在指定が可能）。追加で消費するSKUはない
  - 地図表示はしない（Dynamic MapsのSKUを消費しない）。結果はテキスト表示＋Googleマップへのリンクのみ
  - 検索1回 = API 1リクエストを原則とする（代替ルートは `computeAlternativeRoutes: true` で同一リクエスト内取得）
  - アプリ内に月間リクエスト数のカウンターを持ち、初期値8,000件で警告、10,000件で自動停止（値は設定で変更可）
  - Google Cloud側でもクォータ上限の設定を推奨手順に含める（アプリ側カウンターだけに頼らない）
- 注意：無料枠を使う場合でも、Google Cloudプロジェクトへの課金アカウント紐付けは必須。

## 4. 「最安値」の定義（重要・制約）

Google Routes APIの `transitFare`（推定運賃）は、「APIが全ステップの運賃を
特定できる場合にのみ」返される（Google公式ドキュメント明記）。
したがって本アプリの「最安値」は次の意味に限定する。

- 定義：APIが返した候補ルート（本ルート＋代替最大3件）の中で、運賃が取得できたものの最安
- 運賃が返らなかったルートは「運賃不明」として分けて表示し、最安判定には含めない
- 以下は保証対象外（アプリ内にも注記する）：
  - 日本全国の全経路を網羅した真の最安（APIの候補は最大4件）
  - IC運賃と切符運賃の区別（APIの返値は推定運賃1種類）
  - 特急料金・グリーン料金・座席指定料金などの追加料金
  - 定期券・回数券・1日乗車券を使った場合の実質最安

## 5. 機能要件

### 5.1 入力

- 出発地：デフォルトは現在地（GPS）
  - ブラウザの Geolocation API で緯度経度を取得し、Routes APIの出発地に latLng としてそのまま渡す。最寄り駅は結果の最初の乗車駅として表示されるため、座標→駅名の変換はしない
  - 取得はページ表示時または「現在地から」ボタン押下時。ブラウザの許可ダイアログはユーザーが許可する
  - 画面には「現在地（精度 ±○m）」と表示し、精度が悪い（目安1,000m超）場合は警告を出す
  - 許可拒否・取得失敗・精度不足のときは、手入力（駅名または住所、前回値を初期表示）にフォールバックする。手入力への切り替えはいつでも可能
  - 制約：Geolocation はセキュアな接続（localhost または HTTPS）でのみ動作する。PCブラウザの localhost は可。スマホからPCのLAN IP（http）で開いた場合は動作しない（§9参照）
- 目的地（文字列。駅名または住所）※必須入力は実質これだけ
- 出発タイミング：デフォルトは現在時刻（＝次の便から検索）
  - 「今から○分後」は任意の調整項目として残す（0〜180分、初期値0）
  - 内部で現在時刻（Asia/Tokyo）＋○分を計算し、RFC3339 UTCで `departureTime` に渡す
- 条件変更UI（プルダウン）：検索条件はプルダウンでも変更できること
  - 出発時刻：現在時刻／今から15分後／30分後／1時間後などのプリセットをプルダウンで選択できる（「今から○分後」の数値入力による細かい調整も併用可）
  - 出発地（現在地）：現在地（GPS）／検索履歴／手入力した地点をプルダウンで切り替えられる
  - 目的地：検索履歴や候補をプルダウンで選択して変更できる
  - プルダウンで条件を変更した場合は、その条件で再検索できる（条件自体が変わるため、並び替え変更と違いAPIリクエストが発生する）
- 並び替えモード（4択、初期値は「総合おすすめ」）：
  1. 総合おすすめ（デフォルト）：最安・最短・乗り換え最少を同時に見る（定義は §5.2）
  2. 安さ優先：運賃の安い順 → 同額なら乗り換え少ない順 → 同じなら所要時間短い順
  3. 乗り換え少なさ優先：乗り換え回数少ない順 → 同じなら運賃安い順
  4. 早さ優先：到着が早い順 → 同じなら運賃安い順

### 5.2 検索処理

- Next.jsのRoute Handler（`/api/routes`）がサーバー側でRoutes APIを呼ぶ（APIキーをブラウザに出さない）
- リクエスト条件：
  - `travelMode: "TRANSIT"`
  - `computeAlternativeRoutes: true`（候補は最大4件）
  - `languageCode: "ja-JP"`、`units: "METRIC"`
  - フィールドマスクはEssentials SKUの範囲に収まるものだけを指定する（Pro／Enterprise扱いになる項目は要求しない）
- 乗り換え回数の算出：電車ステップ数 − 1（徒歩ステップは数えない）
- 総合おすすめ（デフォルト）の順位付け：
  - 候補（最大4件）ごとに「運賃・所要時間・乗り換え回数」を取り、候補内でそれぞれ最小=0・最大=1に正規化する（全候補同値なら0）
  - スコア = 運賃 0.4 ＋ 所要時間 0.3 ＋ 乗り換え 0.3（小さいほど上位。重みは定数として1か所にまとめ、後から変更可能にする）
  - 運賃が不明なルートは総合おすすめの先頭にしない（運賃が取れた候補がある場合は後ろに回し、全候補が不明なら所要時間と乗り換えだけで順位付けする）
  - 各指標の単独1位には「最安」「最短」「乗り換え最少」のバッジを付け、先頭カードには「総合おすすめ」を付ける。1件が3指標とも1位ならそのまま「最安・最短・乗り換え最少」と表示する
- 同一条件の再検索は60秒キャッシュし、API消費を抑える

### 5.3 結果表示（ルートごとに1カード）

- 運賃（取得できた場合のみ。できなければ「運賃不明」）
- 出発時刻 → 到着時刻、所要時間
- 乗り換え回数
- 内訳：路線名・乗車駅・降車駅・発着時刻・停車駅数、区間ごとの徒歩
- ルート概要（テキスト表示）：出発地から目的地までの流れ（乗車駅→路線→乗換駅→…→降車駅）を1〜2行のテキストで要約して表示する。ルートの表示はテキストで足りるものとし、地図への描画やグラフィックなルート線表示は行わない
- バッジ：先頭カードに「総合おすすめ」、各指標の単独1位に「最安」「最短」「乗り換え最少」
- 先頭カードでは、乗る電車の出発時刻（＝現在時刻から乗れる次の便）を大きく表示する
- Googleマップで開くリンク

### 5.4 エラー表示

- ルートが見つからない／運賃が全件不明／APIエラー／無料枠ガード到達を、それぞれ区別して表示する
- APIキーが未設定の場合は、設定手順への案内を表示する

## 6. 非機能要件

- 技術構成：Next.js（App Router）＋ React ＋ TypeScript。DBなし、保存はブラウザのlocalStorage（検索履歴と月間カウンター）
- 起動：ユーザーのPCで `start.bat` ダブルクリック → `http://localhost:3000`
- 配置先：D／Eドライブの短い英語パス（Cドライブ逼迫とOneDrive同期を避ける、従来方針どおり）
- セキュリティ：APIキーはサーバー側環境変数 `GOOGLE_MAPS_API_KEY` のみ。Google Cloud側でキーにAPI制限（Routes APIのみ）と上限設定を行う手順書を同梱する

## 7. スコープ外（v1ではやらない）

- リアルタイムの遅延・運休情報の反映保証
- 地図の描画およびルートのグラフィック表示（ルート概要は §5.3 のテキスト表示で代替する）
- 到着時刻指定の検索（v2候補）
- バスだけのルート最適化、定期券を考慮した運賃計算
- スマホ向け公開・ホスティング（個人PC内利用のみ）

## 8. 受け入れ条件

1. 目的地を入れて検索すると（出発地は現在地GPS、出発は現在時刻がデフォルト）、次の便からの候補が時刻・運賃（取得時）・乗り換え回数つきで表示され、先頭が総合おすすめ（最安・最短・乗り換え最少の総合順位）になっている
1b. GPSの許可を拒否した場合は手入力に切り替わり、その旨が画面に出る。GPS取得時も追加のAPIリクエストは発生しない（検索1回=1リクエストのまま）
2. 並び替えモードを切り替えると、定義どおりの順序に並び替わる
3. 運賃が取得できないルートは「運賃不明」と表示され、最安表示と混同されない
4. 月間カウンターが動き、設定した上限で検索が自動停止する
5. APIキーなしでもアプリが起動し、エラーの代わりに設定案内が出る（モックデータでの画面確認を含む）
6. テスト合格と本番ビルド成功をMuse側で確認してから交付する。実キーでの取得確認はユーザーのPCでのみ可能

## 9. 未確定事項（ユーザーの判断が要るもの）

- 出発地のデフォルト：現在地GPSに決定（2026-11-17ユーザー選択）。座標を latLng で直接渡すため追加APIは不要
- 主に使う端末：PCに決定（2026-11-17ユーザー選択）。PCブラウザの localhost で使う前提とし、GPSはWi-Fi測位ベースで精度は環境依存であることを画面の精度表示でカバーする。スマホ向けのHTTPS公開はスコープ外（将来必要になったら別途追加）
